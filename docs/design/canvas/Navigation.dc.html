Navigation rules

Shape

Launch gates→Sign in→Tabs→Secondary screens→Sheets, dialogs

Five tabs in a StatefulShellRoute.indexedStack: Home · Shop · Ask Atom · Orders · Account. Each tab keeps its own back stack, scroll position and filters when you switch away and back. Tab roots have no back button; every pushed screen does. Ask Atom opens full screen over the current tab with a Close (×) and returns to that tab.

Back, everywhere the same

Secondary screenPops one screen. The app-bar arrow, Android back and the iOS edge swipe all call the same pop(); no screen hard-codes where back goes.
Shop, Orders, Account rootGoes to the Home tab.
Home rootLeaves the app (Android's predictive back shows the launcher).
Apply wizard stepPrevious step, with what was typed kept.
Form with changes"Discard your changes?" — Keep editing (default) or Discard.
While sendingBlocked until the request finishes, then the result shows.
Sheet or dialog openCloses it first.
CameraCancels the capture; back to Documents.
Update, Maintenance, First runcanPop: false. Back leaves the app; nothing behind them is reachable.

Android: enableOnBackInvokedCallback="true"; guards use PopScope, never the deprecated WillPopScope.

Guards, checked on every navigation

  1. Version below min_version → Update required.
  2. Maintenance (flag or any 503) → Maintenance.
  3. No consent recorded → First run.
  4. No token → Sign in, remembering ?from=/the/route.
  5. 401 or 403 on any call → token cleared, "You've been signed out", then Sign in with from. Never loops.
  6. No limit yet on a limit-only route → Home (no limit).

Gates use go(), which replaces the stack, so Back cannot step past them. Sign-out also uses go('/signin'): Back from Sign in leaves the app rather than showing an account that is no longer signed in.

Links open with their parent underneath (order → Orders tab), so Back works the same as normal use. They pass through every guard first; signed out → Sign in → the link. No tokens or personal data in any URL. [not built yet] atompay.shop has no /.well-known/assetlinks.json or apple-app-site-association.

No duplicates, no dead ends

  1. A tap that navigates disables its control until the new screen is shown: a fast double tap opens it once.
  2. Pushing the route that is already on top does nothing.
  3. Tapping the current tab scrolls to the top, then pops back to that tab's root.
  4. Every route is in one typed route table; a test opens each one, and each Account and Settings row, and checks the screen it lands on.
  5. Links leaving the app show ↗ and open in the browser or store.

Rate us

The Account row opens the Rate AtomPay screen; its button opens the store listing (App Store with ?action=write-review). No rating question first. The in-app prompt, through the store's own API, comes at most after an on-time payment, never after an error and never with a reward.
